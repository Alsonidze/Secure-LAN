# Secure LAN (LAN Sentinel)

> **Интеллектуальная система мониторинга локальной сети**  
> Информационно-аналитическая система обнаружения и анализа несанкционированных устройств в локальной сети.  
> Курсовой проект по дисциплине «Информационная безопасность» / «Сетевые технологии».

---

## 1. О проекте

**Secure LAN** — это современное локальное веб-приложение, предназначенное для непрерывного контроля состава оборудования в локальной сети (LAN). Система реализует замкнутый аналитический цикл:
$$\text{OBSERVE} \longrightarrow \text{IDENTIFY} \longrightarrow \text{ANALYZE} \longrightarrow \text{INVESTIGATE} \longrightarrow \text{AUTHORIZE} \longrightarrow \text{AUDIT}$$

Приложение не выполняет агрессивных или деструктивных атак (пакетных инжекций, подбора паролей, DoS). Оно ориентировано на пассивную защитную инвентаризацию, детекцию аномалий и протоколирование административных решений.

---

## 2. Ключевые возможности

1. **Круговой интерактивный Network Radar**:
   - SVG/CSS визуализация топологии сети с детерминированным позиционированием узлов по хэшу MAC-адреса;
   - Плавная радиальная анимация сканирующего луча (Radar sweep);
   - Цветовая дифференциация: **Зелёный** — доверенное (Trusted), **Янтарный** — временный доступ (Temporary), **Красный** — неизвестное/инцидент (Unknown) с волновой анимацией пульсации (Ping), **Серый** — не в сети (Offline);
   - Интерактивные всплывающие карточки параметров при наведении и открытие досье по клику.

2. **Аналитический цифровой отпечаток (Device Fingerprint)**:
   - Формирование устойчивого идентификатора узла формата `FP-XXXX-XXXX-XXXX` на основе нормализации аппаратного MAC-адреса, имени хоста (hostname), вендора сетевого адаптера (OUI) и типа оборудования;
   - Вычисление 256-битного криптографического хэша SHA-256;
   - Прозрачный расчёт степени достоверности идентификации (*High / Medium / Low*).

3. **Модель доверия (Trust Model)**:
   - `UNKNOWN` — узел впервые зафиксирован в сегменте и отсутствует в белом списке;
   - `TEMPORARY` — администратор предоставил временное разрешение (гостевой доступ);
   - `TRUSTED` — постоянное доверенное оборудование инфраструктуры;
   - `REVOKED` — доверие отозвано вручную администратором.

4. **Временная авторизация (Temporary Access)**:
   - Предоставление доступа на фиксированный срок (30 мин, 1 ч, 2 ч, 8 ч, до конца дня или произвольное время);
   - Фиксация серверной метки времени `expires_at` в базе данных;
   - Автоматический возврат в статус `UNKNOWN` по истечении срока независимо от перезапуска сервера;
   - Регистрация событий и записей аудита.

5. **Автоматическое аналитическое объяснение инцидентов**:
   - При обнаружении неизвестного узла формируется карточка инцидента `INC-2026-XXXX`;
   - Автоматически составляется мотивированное экспертное заключение с перечнем доказательств (Evidence);
   - Исключены ложные или преувеличенные заявления («Hacker detected»).

6. **Режим расследования (Investigation Mode)**:
   - Вертикальная интерактивная хронологическая лента (Timeline), собирающая в единый поток сетевые события, авторизационные действия и аудит конкретного узла;
   - Фильтрация по типам событий (Сетевые, Авторизация, Инциденты, Аудит).

7. **Неизменяемый журнал аудита (Audit Log)**:
   - Append-only журнал административных действий;
   - Фиксация субъекта (Local Administrator), времени, типа действия и объекта;
   - Защита от редактирования и удаления через интерфейс;
   - Экспорт в CSV с поддержкой кириллицы (UTF-8 BOM).

8. **Два режима работы**:
   - **Demo Mode**: Встроенный полнофункциональный симулятор сети с базовым набором 5 доверенных узлов и панелью демонстрации («Симуляция неизвестного узла», «Истечение срока доступа», «Сброс демо»);
   - **Live Mode**: Пассивное получение доступных данных о сетевых узлах локального сегмента средствами ОС без повышенных привилегий.

## 3. Технологический стек

### Frontend:
- **React 19** + **TypeScript**
- **Vite 8**
- **Tailwind CSS 4**
- **Lucide React** (набор иконок)
- **CSS / SVG Animations** (Network Radar sweep, node pings)

### Backend & Storage:
- **Node.js** + **Express**
- **sql.js** (WebAssembly SQLite) с сохранением файла базы на диск (`./data/secure_lan.sqlite`)
- Полный REST API для работы с устройствами, инцидентами, аудитом и настройками.

## 5. Быстрый запуск

### Требования:
- Node.js версии 18 или выше
- npm или bun

### Запуск одной командой:
```bash
npm run dev
```

Сервер автоматически запустится по адресу:  
**http://localhost:3000** (или на выделенном порту хостинга).

База данных SQLite создаётся автоматически в каталоге `./data/secure_lan.sqlite` при первом старте и сохраняет все изменения между перезапусками.

## 6. Сценарий показа на защите курсового проекта (3–5 минут)

1. **Исходное состояние**:
   - Откройте **Панель управления**.
   - Обратите внимание на статус: `NORMAL` (зелёный индикатор), 5 устройств в сети, 5 доверенных, 0 неизвестных, 0 открытых инцидентов.
   - Продемонстрируйте **Сетевой радар** со спокойным вращением луча и зелёными узлами.

2. **Обнаружение неизвестного узла**:
   - Нажмите кнопку **«Симуляция неизвестного узла»** (в шапке или на панели демо).
   - На радаре появляется красный узел с пульсирующей анимацией (ping).
   - Появляется всплывающее уведомление (Toast): *«Зафиксировано неизвестное устройство 192.168.1.47»*.
   - Статус сети переходит в `ATTENTION REQUIRED`, счётчик неизвестных увеличивается до 1, создаётся открытый инцидент.

3. **Анализ инцидента и Fingerprint**:
   - Кликните по появившемуся красному узлу на радаре.
   - Покажите сформированный **Device Fingerprint** (например, `FP-8C7A-1542-91B3`) и нажмите «Детали отпечатка» — объясните, из каких нормализованных признаков рассчитан SHA-256.
   - Откройте вкладку **«Инциденты»** и покажите автоматическое аналитическое заключение и блок доказательств (Evidence).

4. **Расследование (Investigation Mode)**:
   - Нажмите **«Расследование активности»**.
   - Продемонстрируйте вертикальную ленту событий (Timeline): обнаружение узла $\to$ генерация отпечатка $\to$ классификация как неизвестного $\to$ открытие инцидента.

5. **Временная авторизация**:
   - Нажмите **«Временный доступ»** и выберите срок 2 часа.
   - Статус устройства меняется на `TEMPORARY`, узел на радаре становится янтарным, на карточке устройства начинает обратный отсчёт таймер.
   - В ленте расследования и журнале аудита появляется соответствующая запись.

6. **Симуляция истечения срока**:
   - Нажмите в нижней панели **«Истечение временного доступа»**.
   - Срок принудительно истекает: статус возвращается в `UNKNOWN`, на радаре узел снова становится красным.

7. **Постоянная авторизация (White-list)**:
   - Нажмите **«Доверить постоянно»**, укажите наименование («Гостевой ноутбук инженера») и подтвердите.
   - Статус становится `TRUSTED`, узел на радаре загорается зелёным.
   - Инцидент автоматически закрывается с резолюцией.
   - Статус сети возвращается в **NORMAL**.

8. **Аудит**:
   - Перейдите в раздел **«Журнал аудита»** и продемонстрируйте хронологию всех выполненных административных действий без возможности их модификации.
